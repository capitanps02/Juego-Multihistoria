# MULTIHISTORIA — UI HANDOFF

**Fecha del handoff:** 13 de septiembre de 2026  
**Estado:** dirección visual cerrada para la beta de interfaz.  
**Fuente canónica:** `prototype/index.html`

Este paquete contiene todo lo necesario para continuar la interfaz de Multihistoria en otro proyecto sin perder las decisiones ya tomadas.

## Qué abrir primero

1. `prototype/index.html` — prototipo navegable actual y referencia principal.
2. `docs/UI_CANON.md` — decisiones visuales y reglas que no deben romperse.
3. `docs/SCREEN_SPEC.md` — definición de todas las pantallas.
4. `design_system/TOKENS.json` — tokens visuales y de interacción.
5. `docs/CONTINUATION_PROMPT.md` — prompt listo para pegar en un nuevo proyecto/conversación.

## Dirección actual

La dirección seleccionada es **Premium cinematográfico + Apple-inspired product design**:

- El protagonista es la vida del futbolista, no la interfaz.
- La UI debe desaparecer visualmente cuando el contenido narrativo importa.
- Navegación y controles pueden usar materiales tipo vidrio.
- El contenido usa superficies sólidas, calmadas y de alto contraste.
- Simulación rápida entre eventos.
- Decisiones importantes sobre imágenes/cinemáticas.
- Pocas acciones visibles a la vez.
- Modo oscuro como experiencia principal.
- Azul como acción primaria.
- Dorado como acento de identidad, no como CTA general.
- Transiciones, foco y escala aportan game feel.

## Regla de oro

**No convertir Multihistoria en un Football Manager, una hoja de estadísticas o un dashboard web.**

La interfaz debe responder siempre a:

> ¿Qué está pasando ahora?  
> ¿Qué necesita decidir el jugador?  
> ¿Qué puede ignorar hasta que quiera profundizar?
