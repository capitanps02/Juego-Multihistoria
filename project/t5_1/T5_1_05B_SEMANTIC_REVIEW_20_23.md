## Scope

Compare the **18 canonical callbacks** for phase 20–23 against the **18 runtime rows** in `src/content/events/20_23/conditional-events.ts`.

The runtime phase is generated by one shared factory. Every row receives the same generic scene:
- body: a prior consequence reopens a decision;
- visible: the event has a recognizable prior cause;
- uncertain: the weight/intention of that cause is unknown;
- choices: `Actuar ahora / Esperar / Moverlo por otro canal`.

Therefore titles/gates can show design lineage, but the active runtime callback does not prove the canonical scene, choice set or function.

### `CEVT_21_MEDIA_01`
Canonical title: **La frase recortada**.

Canonical condition is `SEED_CLARA_CHANNEL` **or** high national heat; canonical scene is a long answer cut into a harsher headline, with Clara able to contextualize or exploit the news. Runtime gate is merely `mediaHeat >= 42` and the shared generic callback scene/choices are used.

Disposition: `exact_id_semantic_collision`. This is not just incomplete prose: the same ID currently denotes a materially different scene/trigger contract.

### `CEVT_22_FREE_01`
Canonical title: **Oferta de enero para julio**.  
Runtime title: **El mercado espera que cedas**.

Canonical condition requires expiring contract **and formal interest**; canonical scene is a high-salary preagreement with a club in sporting crisis. Runtime only gates on `contract.monthsRemaining <= 7` and uses generic choices.

Disposition: `exact_id_semantic_collision`.

For both semantic-collision IDs, any future rewrite must treat pending saves as content-identity sensitive. Keeping the same string ID does not make an old pending decision safe to resume into new choices.

## Migration implications

### Old history
Keep old `history.eventId` values as historical truth. Do not rewrite a generic event the player actually saw into a canonical scene they never saw.

### Pending decision
For a pending 20–23 technical/generic callback:
- do not substitute a new canonical ID/choice set unless same-scene equivalence is independently proven;
- for `CEVT_21_MEDIA_01` and `CEVT_22_FREE_01`, even preserving the string ID is unsafe if the new content changes the pending scene/choices;
- use content identity/version compatibility or fail explicitly rather than showing a different decision after reload.

### Exact `CEVT_21_ABR_01`
This is the closest exact-ID case, but its current generic A/B/C decision is still not the canonical decision. Treat pending legacy instances as old-content decisions unless a migration layer can preserve the old choice contract.
