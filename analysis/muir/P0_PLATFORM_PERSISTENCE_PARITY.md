# MUIR P0 — Platform and persistence parity audit

Baseline: `36d3d1b0750b0ded877e55953f223e2de1169a46`

Status: **SOURCE_PARITY_CONFIRMED / EXECUTION_PENDING**

## Shared authority

All three product targets ultimately consume the same production UI source `web/game-ui.js` and the same `GameSession` implementation.

| Target | GameSession | UI | CSS | Persistence | Cinematics |
|---|---|---|---|---|---|
| Web | `dist/session/game-session.js` | direct `web/game-ui.js` | direct `web/game-ui.css` | shared IndexedDB store | default web asset URL |
| PlayCanvas | transitive source bundle from `src/session/game-session.ts` | generated from `web/game-ui.js` | embedded from shared CSS | same IndexedDB store implementation | PlayCanvas asset lookup |
| Android offline | copied `dist/` | copied `web/game-ui.js` | copied shared CSS | same IndexedDB store implementation | local-origin default path; K-01 source graph repaired |

There is no authorized separate Android UI.

## Persistence invariants

`createIndexedSaveStore` is shared by product UI targets:

- active + previous recovery copy;
- SHA-256 integrity per stored raw snapshot;
- validation before write;
- compare-and-swap conflict protection;
- strict IndexedDB transaction durability request;
- legacy localStorage bytes copied, not deleted;
- corrupt recovery data is not silently promoted.

UI import uses `GameSession.migrateFromSave`, preserving the engine as migration authority.

Android adds native file chooser/save bridges for JSON import/export but does not implement a separate game-state format.

## Target-specific storage keys

Storage keys are intentionally platform-specific:
- Web default: `historia-jugador.session.v1`
- PlayCanvas: `historia-jugador.playcanvas.2593315.session.v1`
- Android: `historia-jugador.android.offline.session.v1`

The UI explicitly tells the player local and PlayCanvas saves are separate and supports download/import transfer. MUIR must not present this as cloud synchronization.

## Source parity risks

- PlayCanvas is generated and must be rebuilt after shared-source changes; its manifest hashes generated inputs.
- Android is generated by copying built engine/shared web modules; a clean build is required after graph changes.
- Android uses WebViewAssetLoader secure local origin and blocks non-packaged requests.
- Android currently declares portrait orientation; landscape remains a P0 measurement/check target, not an orientation redesign.
- Platform source parity is not equivalent to runtime certification. Exact-head build/test evidence is still required.

## P0 conclusion

No gameplay/persistence divergence requiring a visual fork was found. K-01 was a packaging omission, not a separate Android implementation; the source graph repair keeps the one-UI architecture intact.
